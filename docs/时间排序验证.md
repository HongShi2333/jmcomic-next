## 当前实现

- 同人等有效分类、不带排除条件：保留实测有效的 `categories/filter` 时间榜单。
- 普通标签、作者或组合搜索的日/周/月：走官网 `/search/photos`，携带 `main_tag/search_query/page/o/t`。
- 分类附带排除条件：官网 `/search/photos/{分类}`，分类限定保留在路径，排除词保留在查询中。
- Cosplay/3D：作为标签查询，不再冒充普通分类。
- 最新、最多浏览、最多喜欢、最多图片：仍使用原 API 通道。
- 官网主机读取 `setting.main_web_host`，缺省使用上游既有主站。
- 新通道共享现有 DoH 与连接池，可取消，单次调用最多 12 秒。它不会在失败时回退成“全部时间”搜索。
- 验证页、错误页、跳转丢失条件和解析不完整均返回错误，不伪装成空榜单。

这些是抓取时的快照，榜单会变化。真正结果区的编号顺序不同，不再只验证请求参数。

确认了两个客户端问题：

1. 网页无匹配结果时，会在下方显示“猜你喜欢”。旧解析器选择整页 `thumb-overlay`，误把相同推荐当成三个榜单。现在仅解析 `col-xs-12 col-md-9 col-sm-8` 搜索列中的 `list-col` 卡片；“没发现A漫”和“找不到和…相符”按空结果处理，推荐和侧栏不会混入。
2. 官网搜索每个接口页为 12 本；移动 API 为 80 本。现在按通道使用正确大小，再由应用分页控制器拼成每展示页 40 本，避免 12 本被误判为末页。

总数仅从搜索摘要的直接子节点读取，数字关键词不会冒充总数。封面先读取 `data-original`，不再拿 `blank.jpg` 占位图。主站失效时从官方发布页选取最多两条替代线路，保留原时间/关键词/页码，成功后复用线路；不关闭证书校验。

已补充与真实 HTML 结构一致的解析回归和 12→40 分页回归。最终编译、测试、Lint 与 Android 6 验证结果见 `历史记录.txt`；当前未连接 Android 6 设备，只有 API 36 模拟器镜像，不能将静态兼容检查当作 Android 6 实机通过。
